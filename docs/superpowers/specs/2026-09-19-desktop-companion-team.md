# Xiao Rong desktop companions and real teams

## Outcome
ColdX companions remain visible while the main desktop window is minimized or in the background. Real native task states drive expressions. Pending choices and approvals surface on the desktop and open their owning task. Different colored companions represent real tasks and continuable native subagents. A team conversation lets the user assign a bounded round to multiple agents and see their actual replies.

## Architecture
- A host service `coldxCompanion` projects live native agents, native pending interactions, and public assistant text. It never exposes reasoning text, raw tool output, credentials, or file contents to the desktop window. It keeps bounded team metadata and messages in the ColdX profile. The native DSH session remains authoritative.
- RPC methods `snapshot({})`, `createTeam({parentSessionId,name,members:[{name,role,color}]})`, `send({teamId,text})`, `stop({teamId})` and `removeTeam({teamId})`. Native continuable children inherit the exact live parent's model/tools/permissions. A user message runs one discussion round: independent responses followed by a single peer-aware synthesis/review if appropriate; no endless autonomous conversation. No parallel write assignments to a shared file by default; roles start as research/design/review and report recommendations to the parent. The UI explicitly says these are real model calls.
- Snapshot version 1: `{version:1,tasks:[{id,parentSessionId?,name,color,mood,caption,pendingId?,updatedAt}],teams:[{id,parentSessionId,name,status,members:[{id,name,role,color}],messages:[{id,taskId?,name,text,at}],error?}]}`. Mood enum `idle,thinking,working,reading,waiting,speaking,listening,celebrating,problem,stopped,sleeping`. Never claim completion on cancellation. Bounds: 24 tasks, 8 teams, 4 members/team, 80 messages/team, 2000 characters/message. Display `caption` max 120. Unknown/unavailable state cannot be labelled successful. Pending states override decorative expression choices.
- Main frontend polls the authenticated host snapshot every 2 seconds, including when minimized. Native session navigation handles root and subagent selection. A sandboxed preload exposes ONLY `window.coldxCompanionDesktop.publish(snapshot)`, `onAction(listener)` and `available:true`. Snapshot includes `{version:1,enabled,reminders,tasks}`; action is `{type:'open',id}` or `{type:'hide'}`. Desktop never accepts approval responses; opening an alert returns to native UI.
- Independent transparent always-on-top BrowserWindow, bounded to the screen work area, showing a compact row of colored furballs and short bubbles. `showInactive`, `skipTaskbar`, secure isolated renderer, local packaged resources only. Main process validates main-frame sender and trusted backend origin, validates bounded data, allows only existing task IDs to open, and clears on workspace switch/reload/disconnect. Exterior transparent space must not block other software; use tight bounds or click-through with safe recovery. Dragging works and saved position is clamped after display changes. App exit closes the pets and backend. Main close keeps current product quit semantics.
- Existing companion settings gain desktop visibility/reminder toggles, with defaults enabled. Hide is reversible from settings. Existing `enabled` remains authoritative and settings are persisted using native settings.
- Group UI in a spacious dedicated dialog/panel, with team/member editor and real-message timeline. Task color deterministic; user can choose from a bounded palette. A pet click opens its actual task; a team control opens the team conversation. Expressions are DOM/CSS over the existing generated fur PNG. Reduced-motion and keyboard accessibility throughout.

## Verification and scope
Use tests with the real native agent loop and deterministic provider to establish genuine child execution, lineage, permissions, no fabricated replies, cancellation, partial failures and bounded rounds. Test IPC frame/origin spoofing, payload limits, stale IDs, teardown, minimization and navigation. Browser-test themes/expressions, team operations, settings persistence and error states. Verify a separate development Electron instance with isolated profile; protect installed user sessions. Publish/update the Windows app after checks, as previously authorized. macOS/Linux implementation follows Electron APIs but is not represented as tested on those OSes.
