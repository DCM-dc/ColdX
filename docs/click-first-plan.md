# ColdX 点击交互实施计划

更新：2026-09-05。目标是以点击、少量输入和效果预览承接用户决策，继续使用 DSH 的真实执行能力。设计依据：[click-first-design.md](click-first-design.md)。验证依据：[verification.md](verification.md)。

## 约束

- DSH 持有唯一根循环、工具执行、权限、会话日志和持久化；ColdX 使用原生工具、投影、carrier 与 client slots。
- 不修改已安装的 DSH 包，不操作用户桌面或提供方密钥，不引入外部服务。
- 普通问题可由 ColdX 呈现；审批与计划审阅保留原生专用通道。
- 新状态边界使用真实运行时测试。视觉修改在浏览器检查，不以 CSS 快照代替效果验收。
- 工作目录是已有交付仓库；不虚构 Git 作者，不丢弃已有更改。

## 任务一：显式交互生命周期

主要文件：`plugin/interaction-{input,host,model}.mjs`、`plugin/page-guard.mjs`、`plugin/policy.mjs` 与原生测试。

`coldx_interact` 承接稳定选项 ID、标签、可选预览、多选与少量自定义输入；原生 carrier 返回实际选择。`coldx_finish` 声明完成，后续业务工具会使声明失效；`coldx.flow` 从原生事件投影状态。
