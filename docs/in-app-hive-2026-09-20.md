# ColdX 小绒群组：应用内伙伴

日期：2026-09-20。用户已取消桌面宠物，开发分支只保留应用内的小绒。未重新安装桌面应用，未改变正式聊天数据。

## 设计结果

- 侧栏小绒保留摸摸、眨眼、注视与状态表情。等待确认、执行受阻优先展示；触摸不会遮盖需要处理的状态。
- 普通会话列表下新增“群组”，点击后在主区域按正常群聊展示。取消大弹窗、小舞台和讨论/成长切页。
- 默认小探（研究）、小画（设计）、小验（审阅）三位伙伴，可修改名字、颜色和分工，成员数为 1–4。紧凑的小绒头像与名字标识发言者，可以打开对应的原生任务。
- 群聊使用固定标题、普通消息列表和底部输入框；真实运行阶段显示在标题和侧栏。经验放在可展开的“群组信息与经验”中，包含适用条件、做法、来源、使用次数，可以试用和停用。
- 眼睛尺寸不随工作、完成、休息等状态持续缩小；说话与报错装饰不会改变眼睛和瞳孔布局。情绪主要通过短暂眨眼、视线与嘴型表达。
- 草稿按父任务和团队隔离，短暂断线后恢复；打开后台子任务前先刷新原生子任务目录。
- 支持浅色、深色、窄窗口、键盘操作和减少动态效果。装饰动效在页面不可见时暂停。

桌面专用窗口、IPC、预加载脚本、桌面伙伴设置与测试已移除。历史桌面验收文档保留并标明已被新方向替代。

## 蜂群研究如何落地

| 资料 | 有用的概念 | 本轮取舍 |

| [AutoGen Swarm](https://microsoft.github.io/autogen/dev/user-guide/agentchat-user-guide/swarm.html) | 能力相关的交接与明确终止条件 | 原生子任务并行探索，审阅成员再汇总，一次发送只执行一轮 |

| [Sakana Darwin Gödel Machine](https://sakana.ai/dgm/) | 候选变更、实际评估与版本档案 | 候选经验标记待验证；保存建议不等于模型训练或性能提升 |

这是有协调者的有限团队协作，不是完全去中心化蜂群。此次没有自改程序、训练权重或自动扩大工具权限。每轮启动 N 次成员任务，另加至多一次审阅汇总。一个子任务可进行多次模型及工具调用，每轮每个成员合计限制为 12 步，不能把任务数当作 API 请求数。经验提炼复用汇总，不另开一次提炼任务。摸摸与表情本身不消耗 Token。

## 经验边界

经验仅在所属团队内使用。每团队最多保存 12 条，最多同时试用 3 条；下一轮最多选取 2 条，连同说明不超过 1200 字符。只有显式开启试用才进入后续上下文，可随时停用。当前用户要求与原生规则优先，经验只是参考数据。

候选来自本轮全员及汇总均完成的公开文本，严格解析三个字段；实际来源任务与消息 ID 由后端生成。取消、失败或保存失败均不能伪造新增成长。使用次数记录实际被交给后续执行的轮数，不代表成功率。完整来源仍在原生任务记录中。

## 验收方式与限制

浏览器视觉验收覆盖浅色、深色、360px 窄窗口、减少动态效果，以及发送失败与断线后的草稿保留。群组与普通会话互斥选择，切换回来恢复各自草稿。源任务打开和经验保存失败均有可恢复反馈。各表情的眼睛与瞳孔尺寸通过浏览器几何断言核验。

另通过实际 ColdX 页面完成：创建三位伙伴 → 分别调用原生子任务 → 审阅成员汇总 → 出现候选 → 开启试用 → 第二轮接收经验上下文 → 使用次数变为 1 → 停用 → 从卡片打开原生审阅任务。

用户调整为普通群组布局后，重新在原生页面核验：侧栏选中群组 → 输入未发送草稿 → 返回原普通会话 → 再次打开群组恢复草稿 → 发送新一轮 → 三位成员回复并汇总 → 点击新会话退出群聊 → 再次打开群组，从小绒头像进入对应审阅任务。普通会话原有草稿保留。

这些验收使用隔离数据目录和本地确定性模型替身，经过真实原生运行时，但没有调用收费模型。它们验证交互、状态与生命周期，不能证明 DeepSeek 输出质量提高。安装包和跨平台发布不在这次验收结论内。

最终构建与回归：`pnpm test` 共 716 项，714 通过、2 项环境条件跳过、0 失败；另行运行客户端/小绒/浏览器场景 22 项全部通过。原生运行时重启和记录重放验证通过，只有已识别的内部空轮次被忽略，其他真实受阻状态保留。
