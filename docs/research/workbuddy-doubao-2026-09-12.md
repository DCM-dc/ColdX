# WorkBuddy、豆包办公任务与 ColdX 的可核实差距

检索日期：2026-09-12。范围：官方产品页、官方帮助文档及 ColdX 当日验收记录。没有安装或登录竞品，文档中的能力是产品方声明，不是本轮端到端实测结果。WorkBuddy 多篇文档在网页检索工具中超时，本轮随后直接请求同一官方 URL，取得 HTTP 200 并读取了正文。

## 产品边界

- **WorkBuddy**：腾讯官方产品页将它描述为可处理本地文件、生成成果、组织专家与多个 Agent 的办公工作台；页面同时介绍本地能力和云端助理。不能据此推断所有本地任务都能在电脑关机后继续执行。[腾讯产品页](https://cloud.tencent.com/product/workbuddy)
- **豆包工作**：本轮可以用字节跳动 Seed 官方 2026-06-23 发布说明确认的入口名称是豆包电脑版/App 的 **“办公任务”模式**。同文另列 **TRAE Work**，二者不可混为同一个产品。该说明展示教案 PPT、表格分析和行业报告等工作流，但模型的 GUI、多 Agent 研发评测不等于豆包产品已开放同等工具和管理界面。[Seed2.1 官方发布说明](https://seed.bytedance.com/zh/blog/seed2-1-officially-released-advancing-ai-productivity)
- 网上检索到的《豆包上线新技能：工作模式深度拆解，企业办公提效实用指南》虽位于火山引擎开发者社区，作者为社区用户，末尾自述结合网络与大模型整理。本报告未把它当作官方产品功能依据。豆包的自动化调度、可管理的并行子智能体、连接器市场、长期记忆设置及来源面板，本轮**未找到足以确认的官方产品说明**，不是断言它们不存在。

## 最适合落地的六项改进

1. **先统一界面骨架。** 左侧固定项目/任务导航；中间保持时间顺序对话与原位输入框；右侧为可收起的工作面板，窄屏再转抽屉。让产物、来源、子智能体、终端共用面板容器、标题高度、间距和关闭行为。只保留一个任务状态入口，降低玻璃、发光和重复浮层的存在感。来源是 WorkBuddy 的结果区结构，具体三栏布局是对 ColdX 的设计建议。
2. **让交付文件先被看见。** 产物列表按“用户成果 → 辅助文件”组织，显示尚在构建、待验收、已验证或部分完成；每项能打开、预览、定位文件，代码改动提供 diff。来源按工作区和规范路径合并，行号是来源内的定位。验收：一项 PDF/表格任务的正式成果能在不读工具日志的情况下找到。
3. **统一执行状态和失败归属。** 主任务、子智能体和命令都从 DSH 真实事件投影状态；子智能体显示承担事项、当前动作、结果、耗时及打开入口。失败、等待用户、等待工具与完成要明确区分。终端没有字节流时照实标记结算输出，禁止以转圈假装实时更新。验收覆盖取消、重试结束、切换会话和重启恢复。
4. **把“自主性”落成小样交付与验证工作流。** 文档先出代表性样张并渲染检查，网页先形成能操作的最小页面，随后批量推进；并行任务只分配边界明确的工作。借鉴豆包官方展示的完整办公产出方向，但用自己的固定测试集衡量首个可用成果耗时、修改轮次和最终质量，不引用模型排行榜证明 ColdX 更好用。
5. **把后台能力做成可管理的任务。** 在原生 jobs/workflows 上补充下次运行、环境、本次状态、停止、历史与失败恢复；清楚标识“本机服务需运行”。Goal 的持续推进与定时调度分别表达，避免让用户误以为打开 Goal 即等于 24 小时托管。云端执行可作为后续独立能力，不能靠前端定时器模拟。
6. **能力和记忆按需可见。** 用统一设置页管理 Skills、MCP/连接器和记忆；提供可用/失效状态、当前任务是否使用、相关来源与可撤销操作。生成质量优先时，先准备可靠的文档、表格、演示与浏览器验证工具链，再扩张市场入口；不要把未连接服务提前列成可执行能力。

## 对本轮 UI 收敛的具体约束

- 标题、分组、空态、错误态、状态标签、菜单和按钮统一尺寸与圆角；模型/权限/模式/附件的相对位置在新会话与已有会话中一致。
- 一个信息只有一个主要入口：输入框放输入相关控制，任务头部放运行状态，右面板放核对详情；缓存统计不占主视觉。
- 产品外壳用中性色、单一强调色、细边框和较低阴影；只有遮罩菜单需要明确深度。动画用于展开、状态切换和焦点反馈，持续呼吸/发光不应成为默认背景。
- 不取消 ColdX 在消息原位生成交互页面的特色。侧栏承载辅助检查，不能把所有生成页面搬走或覆盖对话；页面有真实提交后应继续当前任务。

以上六项为建议，并非声明已在 ColdX 实现。对竞品的能力只确认到官方文档层；对 ColdX 的证据只确认到注明的本地验收范围。

## 本轮已落实的小范围改进与限制

本轮已在活动面板 selectors 中合并同一会话工作区的绝对/相对来源路径，按文件计数，并保留不同有效行号及其调用归属。仅 `.coldx/work/` 下已识别的脚本、日志和临时文件进入默认折叠的过程文件区，其余文件和原位生成页面继续保留。文件成功变更显示“已修改”等操作状态，不宣称成果已经验收。

浏览器复测又发现同一 HTML 文件多次编辑产生重复成果卡片，现已按规范文件路径合并，保留所有相关调用与定位，用最后一次成功变更表示操作状态。成功删除的文件保留记录但不提供打开入口。工作区内的 JSON/JSONL 中间块加入过程文件，HTML 模板仍保守保留在主列表；页面按会话、页面 ID 和版本区分。

**仍有限制：**输出列表依赖已成功的原生 typed 文件变更或 ColdX page 投影。仅经 shell 命令隐式创建、而没有这两类事件的 HTML、Markdown 等文件尚不能自动进入成果列表。因此当前列表不是工作目录所有成果的完整清单；后续应增加明确的产物登记或原生文件变更投影，不能靠解析终端任意文本伪造文件成功记录。
