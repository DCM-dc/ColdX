# ColdX TUI：同一内核的终端入口

日期：2026-09-25

## 目标

让 ColdX 在终端里完成高频的编码对话：选择并恢复会话、发送与中断消息、查看真实工具运行、处理审批。终端界面只承担输入和呈现，DSH Web Host 继续持有模型、工具、会话、权限和插件；桌面与 Web 保留文件、PDF、图片、浏览器及电脑画面预览。

这解决的是网页目前信息密度和交互节奏不佳的问题，不把终端当成一个新的 agent。用户在终端和网页看到的应是同一个会话 ID、同一条事件序列和同一项待审批请求。

## 依据与取舍

Kimi Code 官方把 TUI 的主体定义为输入框、对话流、状态栏；`/` 命令和 `@` 文件补全、运行中插话、工具输出折叠与审批快捷键围绕键盘工作。[交互说明](https://www.kimi.com/code/docs/en/kimi-code-cli/guides/interaction.html)、[快捷键](https://www.kimi.com/code/docs/en/kimi-code-cli/reference/keyboard.html)。其 CLI 与 Web 共享本地会话数据，Web 负责富格式、文件差异、全局搜索和任务面板。[Web 与 CLI 的关系](https://www.kimi.com/code/docs/en/kimi-code-cli/guides/web.html)。ColdX 借鉴这种分工，不移植 Kimi 的代码或把所有网页能力硬塞进字符终端。

当前锁定的 `@deepseek-ai/dsh@0.1.1-rc.2` 没有可直接启动的交互式 `tui` profile；已有 `web` 与 `headless`。因此实现独立的终端客户端，连接**已经运行**的本机 ColdX Web Host。Host 的原生 `/api` 与事件流提供会话列表、历史、发送、中断及审批。终端不读取或另写会话数据库，不启动第二个同目录 Host，也不复制模型执行循环。连接前检查 Host 身份，避免误接其他本机实例。

## 首个可用切片

1. `pnpm tui --url http://127.0.0.1:3086` 连接运行中的 ColdX。明确提示先启动 Host；退出 TUI 不停止 Host。
2. 列出现有会话，选择后回放历史，再订阅实时事件。重连时按事件序号补读，避免重复展示或漏掉工具结果。
3. 终端显示用户/助手文本、折叠的工具摘要、运行/等待状态和真实错误；长输出可展开，绝不编造 Shell、Python 或 C 的执行输出。
4. 发送走原生 `session.prompt`，中断走原生 `session.cancel`。审批面板使用 Host 发来的请求 ID 回答；另一端先处理时同步清掉待审批状态。
5. `/help`、`/sessions`、`/new`、`/cancel` 和 `/open` 只执行有真实通路的动作；`/plan`、`/goal` 等交给 DSH 原生命令通道。`/open` 打开 Web 首页，用户再选中当前会话查看富媒体；目前尚无经过验证的会话直达链接。

首版暂不把生成式页面、图片、PDF 或电脑画面转成伪终端截图。初次进入会话读取 Host 最近的消息窗口；若 Host 报告还有较早历史，终端明确提示到 Web 查看。`/` 和 `@` 的即时补全、运行中插话、完整 Shell 模式、跨端草稿同步与安装包自动启动由后续切片实现，必须分别经过真实运行验收，不能只做菜单项。新建空会话上的 `/plan` 与 `/coldx-goal on|off` 会暂存到首条真实消息提交前应用，单独切换模式不会制造一条非空对话。

## 验收

- 在独立测试 Home 中启动一个 ColdX Host，TUI 可列出同一会话 ID，并回放已有消息。
- 用 TUI 发送到本地测试模型，Web 同会话出现这条消息与回复；工具和审批状态能在两端对应。
- 中断或断线后，TUI 可恢复会话并补齐实际事件；不会新建隐藏会话或重复执行请求。
- 非交互终端输出清楚的文字结果，终端尺寸变化不会丢失当前输入；Windows PowerShell、macOS Terminal、常见 Linux 终端分别验收后才称跨平台可用。
- 不同 Host、不可连接端口、审批已被另一端处理都显示可理解的错误，不出现虚假的成功状态。
