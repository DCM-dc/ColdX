## 接入测试的结论

对用户提供的 `https://unlimitds.chat/v1` 及本轮提供的凭据进行测试：

| 测试 | 实际结果 | 能说明什么 |
| --- | --- | --- |
| 带凭据 GET /models | HTTP 200，返回 Flash、Pro、Vision 及其变体 | 网关入口接受这把凭据 |
| 不带凭据 GET /models | HTTP 401，invalid_api_key | 模型列表并非无需鉴权的公开响应 |
| Flash 非流式最小文本请求 | 约 30.2 秒后 HTTP 401，authentication_failed | 推理请求失败，不能把模型列表成功当作生成可用 |
| Flash 流式最小文本请求 | 约 30.6 秒，HTTP 200；SSE body 中 status_code=401、Authentication failed | HTTP 状态码不能替代流内错误判断 |
| ColdX 原有提供方，上传测试文件后发消息 | 文件引用成功，随后 PI_AI_ERROR / Authentication failed | 上传链路可用，此路由的模型读取未通过验收 |

结合前两项和错误返回的差别，更像网关上游鉴权失败；这仍是推断，最终原因需要网关服务端日志。该目录没有 canonical `deepseek-flash`，不能仅凭名称宣称此网关提供 V4.1。

测试过程中，用户另外将原生提供方改为 DeepSeek 官方地址并更新了凭据。没有覆盖用户的这些新改动。随后在用户当前会话中只读观察到 PDF 提取、Python / PowerShell 执行及文件读取成功，页面显示的累计缓存命中率从约 86% 上升到 94%。这是后续官方配置的观察结果，与上述网关测试分开记录；还不能据此认定最终译文或页面质量合格。

## 本轮已发现并处理的问题

- 图片大图预览：原 fixed div 受 composer 的 backdrop-filter containing block 限制。改为原生 modal dialog / top layer。实际浏览器复测覆盖完整 1280×720 视口，Escape 后焦点回到缩略图。
- 缓存统计：零输入的新会话原来显示缓存 0%。现在等有有效输入 token 后才显示命中率；有真实输入而零命中的情况仍正确显示 0%。
- Goal 会话恢复：重启后旧 `coldx/coding-mode` 事件被 pinned DSH 的严格日志读取器拒绝。修复必须保留原日志、只兼容这个已知事件，同时保留对其他未知必要事件的拒绝。
- 原生 DeepSeek 流式错误：离线真实 adapter + agent loop 复现了 1 次请求加 5 次重试，最终把鉴权错误报成 EMPTY_RESPONSE。补丁固定于现有依赖版本，恢复结构化错误及正确重试分类，不升级 DSH 或替换原生 loop。

后两项的最终测试及加载状态在文末记录。

## 界面与功能验收

- 本机文本文件选择器上传、成功提示、带空格的 @ 引用、实际发送：通过；模型读取是否成功取决于所用提供方。
- 本机图片添加、缩略图、放大、Escape、移除：通过。图片识别的正确性未在失败的网关上验收。
- Coding mode 菜单：Goal 和 Plan 均能选中；页面没有额外的重复 Goal 标签。尚需用实际任务验证目标闭环和计划审批行为。
- 行动镜：能读取真实调用记录、来源和输出；在真实任务中可看到 PowerShell / Python 结算输出、stderr 和 exit code。
- 终端设置入口存在。当前终端实现读取命令完成后的 resultView；本轮没有把它宣传为完整实时 PTY，也未切换用户的终端设置。
- 用户当前任务仍在执行时，不以重启打断其工作。

## 建议按这个顺序完善

1. **连接与模型能力诊断。** 每个提供方同时显示域名、路由、凭据引用和连接状态；模型目录、文本生成、工具调用、图片输入分别检测。网关入口拒绝、上游拒绝、超时、模型名不支持要有不同反馈。模型能力以此提供方实际验证为准。
2. **尽早交付可验证样张。** 文档任务先完成少量代表性页面的提取、翻译、视觉验收，再批量并行。环境能力和已验证的文档处理工具应可复用，减少每次从 PATH 探测、安装依赖、重写抽取脚本开始。以样张准确性和最终产物验收为指标，不能只看调用次数。
3. **让进度说明面向用户。** 中文请求用中文进度；默认收起密集的 Think 记录和注入明细，突出当前动作、完成数量、失败原因与下一步。完整轨迹按需展开，保持原生消息顺序。
4. **来源去重并可打开。** 实测同一 raw.txt 的相对路径和绝对路径被重复统计，不同行号也分成多个来源。应按 workspace + 规范路径聚合，再保留多个精确位置；点击直接打开对应文件或工具证据。
5. **区分交付物与过程文件。** 当前输出区优先出现 extract.py、analyze.py 等中间脚本。应优先展示用户能使用的文档、页面和下载结果；把支持脚本折叠进过程文件，标清尚在构建、已验证、部分完成。
6. **提高运行面板可读性。** 行动镜当前浮层会遮住对话和输入区；宽屏用可调整的并列区域，窄屏再用抽屉。终端增加逐条展开、stderr 样式和实时输出能力；历史重试记录结束后不应继续显示“进行中”。
7. **成本统计支持质量判断。** 显示本轮/会话的未命中输入、缓存读取、输出和重试次数，区分主智能体与子智能体。高命中率不等于低总成本，也不能代替首个可用结果的耗时、任务完成率和产物质量。
