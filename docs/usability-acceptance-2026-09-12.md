# ColdX 可用性修复与浏览器验收

## 已实现

| 用户问题 | 当前行为 |
| --- | --- |
| 输入框有光标却不能键入 | 点击输入卡片空白区域会聚焦原生 textarea，交互控件保留自己的操作；实际点击原故障位置后键入成功。 |
| Goal 无法选中、重复标签、双模式错位 | 原生投影决定模式状态；Goal/Plan 共用 Plan 标签组件，最多各一枚；390px 下组合换行，发送、模型、附件仍可访问。 |
| 模式开关回执刷屏 | 隐藏成功的 Plan/Goal 开关回执，包括旧版没有记录参数的已知 Goal 回执；错误、其他命令仍可见。 |
| 生成页不跟随深色模式 | DSH 主题实时广播给独立 iframe，不重新挂载页面；新页使用主题变量，旧页的独立 light/dark CSS 媒体查询可兼容。HTML 文件预览同样支持。 |
| 文件无法在页面查看、引用 | 工作区文件入口、文件标签、目录导航、Markdown/源码/图片/HTML/PDF 预览；全文或拖选片段可引用，保留当前草稿。只读子会话的引用返回父会话。 |
| 产物没有可用入口 | `coldx_register_artifact` 验证真实文件并登记；原生文件 chip、Markdown 本地链接及工作面板使用同一个阅读器；生成页入口跳到对应消息。 |
| 子智能体失败且状态不明 | 子任务继承父任务实际模型路由及首轮推理等级；修复 Host 与浏览器解码器中的状态传递；进度页显示简洁完成/运行/失败行，默认三项，可展开并进入原生子会话。 |
| 思考和工具记录太长 | 思考与单条工具默认紧凑；连续已完成步骤可组合折叠；错误、正文和生成页保留在消息流，选中工具或恢复锚点时可展开。 |
| 终端只有结算结果 | 设置开启后显示原生命令 stdout/stderr、运行状态及退出码；实际 25 秒命令结束前已看到第一段输出。运行中置顶，关闭设置停止订阅，旧历史读取已结算结果。 |
| 窄屏顶部重叠 | 标题、子代理、任务菜单与文件/工作面板入口按可用宽度换行，窄屏保持独立工具行。 |

## 真实验收

- 使用当前用户配置的官方路由创建独立验收会话（会话编号未公开），实际执行 PowerShell、写入并登记 Markdown、运行子智能体、生成交互页面；子任务实际返回 `SUBAGENT_OK`。
- 输入卡片边缘点击可键入；Goal/Plan 同开同关没有成功回执刷屏；390×844 视口下两枚标签同类同排，顶部没有按钮重叠。
- Markdown 拖选引用保留文件路径及原文；只读子会话能浏览真实工作区，并将引用送回父会话可见输入框。
- 生成页切换主题后保留输入值；旧生成页从深色切为浅色，保留“仅中文”选择；随后恢复原阅读模式。
- 现有含 NUL 的 HTML 可预览；UTF-16、BOM、NUL 或无效 UTF-8 引起的显示转换不会改变下载文件的原始字节。
- 上传的 51 页 PDF 实际显示首页及第 2 页，50% 缩放生效；PDF 文字层可拖选并引用。
- 原生实时命令先显示 `STREAM_FIRST` 和“运行中”，随后显示 `STREAM_LAST` 与 `exit 0`，没有以模拟日志代替运行输出。
- 原有长任务的连续步骤形成折叠摘要，实际点击可以展开并收起；失败记录与最终生成页仍在原位置。修复了原生 details 默认切换与 React 受控状态竞争。
- PDF 翻页、缩放、关闭的真实浏览器复测没有新增错误；取消使用 PDF.js 要求的异常原因，修复迟到消息写入已关闭流的问题。
- 全量测试 **378 项通过，0 失败**，记录：`.runtime/coldx-usability-final-tests-20260912.log`。覆盖原生工具、真实浏览器解码器、父子归属、文件边界、流取消与显示生命周期。最终版本已重启，并在确认原页面没有草稿后刷新加载。
- 浏览器验收后恢复浅色、关闭临时启用的终端设置，测试模式关闭、测试草稿清空。未变更模型密钥。

## 实际边界

- 文件读取限制在所属工作区；正文预览最多 2 MiB，图片/PDF 完整预览最多 8 MiB。超大文件显示截断或转本机打开，不提供伪完整下载。
- PDF 按页渲染、可选择已有文字；扫描件没有 OCR，加密 PDF 需在本机打开。PDF 纸张保持原始颜色，阅读器界面跟随应用主题。
- 单套硬编码颜色、复合媒体条件、脚本自行调用 `matchMedia` 的旧页面不能保证自动换色；新生成页面按主题变量契约实现。
- 终端不是交互式 PTY，不向已运行进程发送 stdin；Python/C 等由原生 shell 启动时，显示其实际 stdout/stderr。未提供输出流的外部工具不伪造输出。
- 文件登记证明文件存在，不能替代内容正确性验收。此前回答中的纯文本文件名不会凭空变成已验证产物；登记结果、实际文件链接和文件浏览器均可打开。
- 桌面 staging 已统一应用并验证当前原生补丁及 PDF 静态资源/许可证复制；本轮未构建或发布 macOS/Linux/Windows 安装包。
- 任务级 diff/worktree、可编辑长期记忆库及跨任务自动化仍是后续范围；本轮完成的是上述交互和运行边界修复。
