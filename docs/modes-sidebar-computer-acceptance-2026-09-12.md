# ColdX：模式草稿、侧栏预览与浏览器操作验收

日期：2026-09-12。延续原生 DSH 会话、工具、权限与附件链路。本文记录实际交付及边界，技术依据见 [DeepSeek computer use 研究](research/deepseek-computer-use-2026-09-12.md)。

## 已完成

- **Goal / Plan 草稿**：首页切换只更新本地模式标签，不执行会话命令；第一次真实消息发送时，在附件准备成功之后同步模式，再提交一次原始消息。取消或失败保留输入与未完成的模式状态。已有会话仍使用原生模式命令。
- **移除空白行**：仅将成功的纯模式切换回执从最外层消息行布局移除，原始日志保留。失败、其他命令、带实际内容的计划输出仍显示。
- **统一右侧栏**：进度、成果、文件共用一个侧栏。会话区域至少 960px 时并排显示 380px 侧栏；至少 1200px 时使用 420px。窄屏改用可关闭抽屉。对话与输入框共同让出空间。
- **文件预览**：Markdown、源码、图片、HTML、PDF 使用同一阅读区；切换侧栏页保留文件标签与 PDF 当前页。引用保留原草稿，并将输入焦点交还会话。
- **浏览器 computer use**：`coldx_browser` 按需启用官方 Playwright MCP 工具，每个任务拥有独立浏览器上下文。截图成为原生图片附件，模型可看图、点击、输入、滚动并验证结果。侧栏显示真实操作、状态和截图；截图可原位放大及键盘滚动。
- **执行状态**：关闭网页后正确显示浏览器已关闭；“结束浏览器会话”可释放对应驱动连接。关闭请求去重，较旧轮询不会将已关闭状态覆盖为开启。子会话读取与关闭均验证父子归属。

## 使用与边界

- 可以直接要求 ColdX：“打开这个网页，查看页面并完成指定操作。”浏览器工具会按需启用；在“工作面板 → 成果”查看画面和操作。
- 当前是**独立浏览器操作**，不控制 Windows/macOS/Linux 原生桌面应用，不连接用户已有浏览器登录状态。多模态模型负责理解图片，浏览器驱动负责实际操作；不是向 DeepSeek 请求一个自动执行的内置 `computer_use` 工具。
- 截图随实际截图工具调用更新，不是视频直播；读取侧栏不会额外截图或向模型增加图片输入。面板最多保留 24 条最近操作和两张图，进程重启后的完整记录仍以原生会话日志/附件为准。
- 看图或侧栏预览时省略截图工具的 `filename`；指定安全的图片文件名表示导出文件，遵循官方 MCP 只返回文件结果的语义。导出位于该会话 `.coldx/browser/<session hash>/` 专用目录。
- 新机器先运行 `pnpm computer:install` 安装官方浏览器组件。已解决本机 full Chromium 启动失败问题，使用官方无头 Chromium 和全新内存上下文。桌面打包依赖与安装脚本已同步，本轮没有发布三平台安装包。
- 文件阅读和引用继续遵守原有工作区、大小、文件类型及只读子会话限制；本轮没有新增 OCR、交互式终端 stdin 或原生桌面鼠标驱动。
